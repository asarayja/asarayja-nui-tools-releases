What it is

A FiveM NUI is a web page drawn over the game. Normally you only see it in game: start the server, join, open the menu, find the bug, edit, restart the resource, repeat. Asarayja NUI Tools shows that page on your desktop instead. It reads the resource's Lua, finds every SendNUIMessage, guesses the data the game would send, answers the page's callbacks, and lets you edit HTML, CSS and JS while the menu is on screen.

Around that sits everything that came up while building a server's scripts: templates for new scripts and phone apps, a rule check for the mistakes that only show on the game's transparent surface, an AI tab that works under those rules, Git, and deploy or a file explorer against the server over SFTP or FTP.

Scenes

Every message Lua can send is a button. Click it and the menu shows that state, filled with data guessed from the script's own config tables.

Editor

CSS applies while you type, HTML and JS on pause. The files as a folder tree, the ones the page really loads marked with a dot.

Check

The NUI rules checked by machine: CSS that breaks in game, blocking dialogs, callbacks without cb(), files missing from the manifest, locale files that disagree.

AI

Claude Code, Codex, Gemini or a local model, always with the rules as its standing instruction. Screenshots of the menu go with the message; every change can be undone per file.

Templates

New script from a template: NUI menu, inventory, clothing menu, loading screen, LB Phone, NPWD and oph3z phone apps. Locales in five languages from the start.

Server

Deploy with one key, or browse the server like FileZilla: fetch a resource, edit it here, send it back. Production servers are marked red and ask first.

A look around

Getting started

  1. Install

    Windows: run the installer, or unzip the portable build anywhere. Linux: make the AppImage executable and run it, or install the .deb. New versions are downloaded in the background and offered when ready.

  2. The first run

    A short setup asks for the app language and which AI you want to use. It looks for the installed command-line tools (Claude Code, Codex, Gemini, Ollama). Everything can be changed later under ⚙ (Ctrl+,).

  3. Open a resource

    Pick folder and choose a resource folder (the one with fxmanifest.lua). Or choose a folder holding many scripts: they are listed under Scripts with the links between them, and the AI can work across them.

  4. Show a scene

    On the Scenes tab every message Lua can send is a button. Show sends it to the page. Open a scene to edit its data before sending. Lists the game fills at runtime are guessed from the script's config; a recorder resource can capture real data in game.

  5. Edit

    Ctrl+E opens the editor next to the menu. Save with Ctrl+S; with Live on, CSS/HTML/JS save by themselves a moment after typing. The Red test paints the page background red so everything that would show the game through is visible.

  6. Check

    The Check tab runs the rules on the resource. Errors and warnings are things that break in game; notes are just notes. Click a finding to open the file at the line, or hand the list to the AI.

  7. Let the AI work

    On the AI tab describe the change. The AI gets the rules with every conversation, can see a screenshot of the menu, and asks before it does anything risky. The changes of a turn are listed with a diff and an Undo per file. Ctrl+Tab switches between the scripts it touched.

  8. Send it to the server

    Under ⚙ → Server add your servers: a local folder, SFTP or FTP, each with a name and a role (production or dev). Deploy (Ctrl+D) replaces the resource on the server and restarts it over RCON. Server opens the file explorer for everything else.

Something went wrong? ⚙ → Updates shows where the log file is; the last 200 lines are what a bug report needs. If the app crashed, a bar at the top offers to copy them.

The rules, in short

The check and the AI follow one rule set, written from what actually went wrong in real scripts. The core of it:

Lua owns focus

Lua opens and closes the menu; Escape in the page sends close to Lua; onResourceStop releases focus.

No blocking dialogs

Never alert, confirm or prompt: they freeze the page in game. Build your own modal.

CSS that survives the game

No backdrop-filter, no transforms on hover, no custom scrollbars, backgrounds on a child element. Test with a red body.

Every callback answers

Every RegisterNUICallback calls cb() on every path, or the page hangs.

The server decides

Prices, access and validity are checked on the server, never trusted from the page.

Locales

Every text the player sees comes from locale files; comments in English.

Hva det er

En FiveM-NUI er en nettside som tegnes over spillet. Vanligvis ser du den bare i spillet: start serveren, koble til, åpne menyen, finn feilen, rediger, restart ressursen, gjenta. Asarayja NUI Tools viser den sida på skrivebordet i stedet. Den leser ressursens Lua, finner hver SendNUIMessage, gjetter dataene spillet ville sendt, svarer på sidas callbacks og lar deg redigere HTML, CSS og JS mens menyen står på skjermen.

Rundt det ligger alt som dukket opp underveis mens scriptene til en server ble laget: maler for nye script og telefonapper, en regelsjekk for feilene som bare vises på spillets gjennomsiktige flate, en AI-fane som jobber under de samme reglene, Git, og deploy eller en filutforsker mot serveren over SFTP eller FTP.

Scener

Hver melding Lua kan sende er en knapp. Klikk, og menyen viser den tilstanden, fylt med data gjettet fra scriptets egne config-tabeller.

Editor

CSS slår inn mens du skriver, HTML og JS ved pause. Filene som et mappetre, de sida faktisk laster merket med en prikk.

Sjekk

NUI-reglene sjekket av maskin: CSS som ryker i spillet, blokkerende dialoger, callbacks uten cb(), filer som mangler i manifestet, locale-filer som ikke stemmer.

AI

Claude Code, Codex, Gemini eller en lokal modell, alltid med reglene som fast instruks. Skjermbilde av menyen følger meldinga; hver endring kan angres per fil.

Maler

Nytt script fra mal: NUI-meny, inventar, klesmeny, loading screen, LB Phone-, NPWD- og oph3z-telefonapper. Locales på fem språk fra start.

Server

Deploy med én tast, eller bla på serveren som i FileZilla: hent en ressurs, rediger her, send tilbake. Produksjonsservere er merket rødt og spør først.

En titt rundt

Kom i gang

  1. Installer

    Windows: kjør installeren, eller pakk ut den portable versjonen hvor du vil. Linux: gjør AppImage-fila kjørbar og start den, eller installer .deb. Nye versjoner lastes ned i bakgrunnen og tilbys når de er klare.

  2. Første gang

    Et kort oppsett spør om språk i appen og hvilken AI du vil bruke. Det leter etter installerte kommandolinjeverktøy (Claude Code, Codex, Gemini, Ollama). Alt kan endres senere under ⚙ (Ctrl+,).

  3. Åpne en ressurs

    Velg mappe og pek på en ressursmappe (den med fxmanifest.lua). Eller velg en mappe med mange script: de listes under Script med koblingene mellom seg, og AI-en kan jobbe på tvers av dem.

  4. Vis en scene

    På Scener-fanen er hver melding Lua kan sende en knapp. Vis sender den til sida. Åpne en scene for å redigere dataene før sending. Lister spillet fyller i sanntid gjettes fra scriptets config; en opptaker-ressurs kan fange ekte data i spillet.

  5. Rediger

    Ctrl+E åpner editoren ved siden av menyen. Lagre med Ctrl+S; med Live på lagres CSS/HTML/JS av seg selv like etter at du har skrevet. Rød test maler sidebakgrunnen rød, så alt som ville vist spillet gjennom blir synlig.

  6. Sjekk

    Sjekk-fanen kjører reglene på ressursen. Feil og advarsler er ting som ryker i spillet; notater er bare notater. Klikk et funn for å åpne fila på linja, eller gi lista til AI-en.

  7. La AI-en jobbe

    På AI-fanen beskriver du endringen. AI-en får reglene med hver samtale, kan se et skjermbilde av menyen og spør før den gjør noe risikabelt. Endringene fra en runde listes med diff og Angre per fil. Ctrl+Tab bytter mellom scriptene den har rørt.

  8. Send til serveren

    Under ⚙ → Server legger du inn serverne dine: lokal mappe, SFTP eller FTP, hver med navn og rolle (produksjon eller dev). Deploy (Ctrl+D) bytter ut ressursen på serveren og restarter den over RCON. Server åpner filutforskeren for alt annet.

Gikk noe galt? ⚙ → Oppdateringer viser hvor loggfila ligger; de siste 200 linjene er det en feilrapport trenger. Krasjet appen, tilbyr en stripe øverst å kopiere dem.

Reglene, kort

Sjekken og AI-en følger ett regelsett, skrevet ut fra det som faktisk har gått galt i ekte script. Kjernen:

Lua eier fokus

Lua åpner og lukker menyen; Escape i sida sender close til Lua; onResourceStop slipper fokus.

Ingen blokkerende dialoger

Aldri alert, confirm eller prompt: de fryser sida i spillet. Lag din egen modal.

CSS som overlever spillet

Ingen backdrop-filter, ingen transform ved hover, ingen egne scrollbarer, bakgrunn på et barn-element. Test med rød body.

Hver callback svarer

Hver RegisterNUICallback kaller cb() på alle veier ut, ellers henger sida.

Serveren bestemmer

Pris, tilgang og gyldighet sjekkes på serveren, aldri stolt på fra sida.

Locales

All tekst spilleren ser kommer fra locale-filer; kommentarer på engelsk.
